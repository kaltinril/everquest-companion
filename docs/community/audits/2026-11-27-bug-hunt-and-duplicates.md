# Bug hunt and duplicate-purpose review (2026-11-27)

The owner: "kick off a series of bug hunt and duplicate code purpose review with different flavors
of AI (haiku, sonnet, opus) and then do a final review of those findings only with fable ... The
duplicated purpose/code items should not be implemented just identified, i need to personally
review what each output change would be." This file is the record.

## How it was run

- Read-only finders: 19 bug finders over 10 areas (Haiku 6, Sonnet 8, Opus 5; one or two per
  area), 4 duplicate reviewers (renderer UI twice, Opus and Sonnet; shared logic, Sonnet;
  main/preload/engine, Haiku). Each finder was handed the area's `requirements/` and plan files and
  the "Refuted" and "Left" sections of `2026-11-19-bug-hunt.md`. Code changed since 2026-11-20
  came first.
- Fable validated only: one Fable agent per area, handed that area's findings, told not to hunt.
- Bugs: 24 reported, 16 confirmed, 3 plausible, 5 refuted or duplicate. Duplicates: 37 reported,
  33 valid or partly valid.
- Areas with no finding: Loot/Factions/Gaps/Bazaar/Maps (sonnet, haiku), Screenshot reader (sonnet).
- Rule for what is fixed: CONFIRMED (or a PLAUSIBLE that rides with a confirmed fix in the same
  code), and not a choice between two defensible rules. Fixes change wrong text or wrong results
  only; no duplicate is merged. Duplicates whose drift is a plain bug are fixed as bugs, without the
  merge (dup-ui-a-1).
